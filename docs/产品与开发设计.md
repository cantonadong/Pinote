# Stick 产品与开发设计

## 1. 产品范围

Pinote 是一个维护多条提醒的极简 Android 原生应用。每条提醒由单行标题和一种内容模式组成：普通多行文本，或包含多条 Todo 的 Todo List，两种模式互斥。全部提醒中最多只能 Pin 一条；系统通知栏只常驻显示当前 Pin 的提醒，取消或删除当前 Pin 后移除通知。

不在范围内：账户、云同步、多提醒、分类、导航栏、Tab、复杂 Toolbar、FAB、卡片化装饰，以及需求稿中的设计说明标签和外围展示文字。

## 2. 核心业务流程

1. 首次进入显示空状态和标题/内容编辑入口。
2. 用户填写标题，或创建文本/Todo 内容块；输入即时落盘。
3. 有效内容出现后启动前台服务并创建常驻通知；后续每次修改刷新通知。
4. Todo 点击整行合理触控区域切换完成状态，状态立即保存并刷新通知。
5. 任一内容块向左或向右拖动：内容跟手移动，底层露出系统红删除区和垃圾桶图标；越过阈值并松手后删除。
6. 删除后列表补位，底部 Snackbar 显示 2 秒；点击“撤销”按原索引、原内容、原状态恢复。
7. 标题及内容全部变为空白后取消通知；再次出现有效内容时恢复。

有效内容统一定义为 `trim()` 后非空；空白 Todo/文本不进入持久数据和通知。

## 3. 页面、交互与状态

主页面从上到下为：页面标题、单行标题输入区、内容区、添加文本/添加 Todo 操作。无额外导航层级。

内容块：

- 文本：多行显示、自动换行；编辑时保留换行。
- Todo：左侧 Checkbox、右侧文本；完成后保留并以勾选、次级文字和删除线表达。
- Checkbox 的最小触控区域为 48dp，整行可切换但编辑态不误触。
- 双向滑动删除阈值建议为可用宽度的 35%，松手前可回弹；越界后执行删除。
- 同一时间只保留最近一次删除的撤销机会；新删除替换旧 Snackbar。

页面状态：

- Normal：有标题和混合内容块。
- Loading：仅用于启动时读取本地数据的短暂占位，不阻塞系统通知恢复。
- Empty：引导添加第一项，不虚构示例数据。
- Error：持久化或通知权限/服务异常，以页内轻量提示呈现并允许重试。
- Edge：长标题、多行文本、长 Todo、已完成/未完成混排，验证换行与布局稳定性。

## 4. 通知逻辑

- Android 8+ 创建低打扰通知渠道；通知使用 `setOngoing(true)`，以前台服务保障常驻性。
- Android 13+ 首次需要通知权限；拒绝后 App 内容仍可编辑，并明确提示无法显示通知及重试入口。
- 结构遵循系统 Notification：单色透明 small icon、标题、内容摘要；内容较多时使用系统 `BigTextStyle`，不自绘 RemoteViews。
- 通知正文按内容块顺序拼接；Todo 使用 `☐/☑` 或平台稳定可读的纯文本标记。
- 编辑事件先持久化，再由单一同步器根据最新快照更新或取消通知，避免 UI 与通知分叉。
- 设备重启后通过受限、合规的启动接收器恢复非空提醒；需在真机上验证不同厂商后台策略。

## 5. 视觉规范

- 视觉基准为仓库根目录 `design.png`。稿中的内容类型标签、功能分节标题、手势箭头与设计说明均为展示元素，不进入产品 UI。
- 使用 Material 3 语义色并克制定制：浅色/深色 System Background、近黑主文字、系统灰次级文字、系统蓝主操作/选中态、系统红删除态。
- 无渐变、重阴影、夸张圆角和不必要卡片；层级主要靠留白、字号、分隔线表达。
- 建议基线：页面水平边距 20dp；主标题 28sp；输入标题 20sp；正文 16sp；辅助文字 13–14sp；行高不低于 24dp；小圆角 10–12dp。
- 图标使用 Material Symbols/Vector Drawable，视觉保持简洁线性。App Icon 后续单独制作 Adaptive Icon；通知图标使用专用单色 Vector。
- 产品明确仅支持浅色模式，不实现 Dark Mode；仍支持字体缩放和系统减少动画偏好，正文对比度目标不低于 WCAG AA。

## 6. 技术架构

- UI：Kotlin + Jetpack Compose + Material 3；单 Activity；独立 Preview/Playground 使用 mock state。
- 状态：单向数据流，`ReminderViewModel` 暴露不可变 `ReminderUiState`；用户事件通过 sealed actions 进入。
- 数据：Room 单提醒表 + 有序内容块表；事务保证删除/撤销及顺序恢复。轻量设置使用 DataStore。
- 通知：Foreground Service + NotificationManagerCompat；同步器只消费持久层快照。
- 依赖方向：Compose UI → ViewModel/use cases → repository → Room；通知同步器依赖 repository，不依赖 UI。
- 测试：纯 Kotlin reducer/use-case 测试、Room instrumentation、Compose UI/手势测试、通知与重启真机测试。

建议模型：`Reminder(id, title)`；`ContentBlock(id, reminderId, type, text, completed, position, createdAt)`。文本块忽略 `completed`，Todo 使用该字段。

## 7. 开发顺序与依赖

1. 独立视觉/交互 Preview：覆盖五类状态、主题、Todo、双向滑动和 Snackbar 时序；用户确认后冻结视觉 token。
2. Android 工程骨架与 Compose Preview：依赖第 1 步确认结果。
3. Room 数据模型、仓库和状态流：通知与 UI 的共同基础。
4. 标题/内容编辑及 Todo 状态：依赖数据层。
5. 常驻通知、权限与空内容取消：依赖稳定数据快照。
6. 双向滑动删除、2 秒撤销：依赖事务和稳定列表 key。
7. 深浅主题、无障碍、图标和像素级收尾。
8. 自动化测试、真机矩阵、生成签名策略明确的测试 APK。

## 8. 验收清单

- 标题单行；文本多行换行；Todo 可反复切换且重启不丢失。
- 内容块严格按创建顺序，左右滑删除行为一致，阈值前回弹。
- Snackbar 文案正确、恰好约 2 秒、撤销恢复原位置和状态。
- 任意编辑在可接受延迟内同步通知；全空取消；重新输入恢复。
- 通知普通滑动不可清除，展开使用系统样式，small icon 合规。
- 浅色模式、长文本、字体放大、旋转/进程重建无破版或丢数据。
